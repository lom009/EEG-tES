# 配置文件说明

本文面向配置使用与维护人员，说明当前桌面程序的配置项和更新机制。默认值以随程序发布的 [appsettings.default.json](../EGGtCSPlatform/appsettings.default.json) 为准；本文所列为仓库当前模板值，发布包的更新源地址可能不同。日志运行机制另见 [日志说明](日志说明.md)。

## 文件位置与修改方法

| 文件 | 用途 |
|---|---|
| 程序目录 `appsettings.default.json` | 当前版本完整默认模板，随安装包和软件更新发布 |
| `%LocalAppData%\EGGtCSPlatform\appsettings.json` | 当前 Windows 用户配置，启动同步后实际读取的文件 |
| 程序目录 `appsettings.json` | 旧版配置；仅在用户配置不存在时用作首次导入来源 |
| `%LocalAppData%\EGGtCSPlatform\config-backups` | 同步及恢复出厂设置所用备份目录，保留最近 5 份 |
| `%LocalAppData%\EGGtCSPlatform\appsettings.DeviceBackend.backup.json` | 模拟模式切换专用备份，与上述轮换备份不同 |

手动修改前退出程序，备份用户配置，编辑需要的字段后重新启动。根节点必须是 JSON 对象；属性名与字符串使用双引号，布尔值为 `true/false`，数字不加引号，空值为 `null`。使用标准 JSON，不添加注释或尾随逗号。时间间隔使用 `hh:mm:ss.fff` 字符串，例如 `"00:00:01.500"` 表示 1.5 秒。

程序不监视配置文件变化（`reloadOnChange: false`），手动修改后必须重启。应用内字号切换等功能有自己的即时应用流程，见后文。不要在程序运行时同时手动改文件，以免与应用保存冲突。

启动时先用模板同步用户配置，再读取用户值；只有本文列出的环境变量会在相应通信选项上覆盖配置，并非所有 JSON 字段都支持环境变量。`ApplicationUpdate.SourceBaseAddress` 始终采用当前模板值，不受用户文件修改影响。

### 请求超时覆盖

八项 JSON 超时默认均为 `00:00:01.500`，要求正值。对应环境变量为正整数毫秒，优先级高于 JSON；非法超时环境值报错，不静默替换。

| JSON：`V101RequestTimeouts.*` | 环境变量 | 等待的请求响应 |
|---|---|---|
| ReadDeviceStatus | EGGTCS_V101_TIMEOUT_STATUS_MS | 读取设备状态 |
| ConfigureEegImpedance | EGGTCS_V101_TIMEOUT_EEG_IMPEDANCE_MS | 配置 EEG 阻抗检测 |
| ControlAcquisition | EGGTCS_V101_TIMEOUT_ACQUISITION_MS | 控制采集启停 |
| ControlStimulation | EGGTCS_V101_TIMEOUT_STIMULATION_MS | 控制刺激启停 |
| AdjustCurrent | EGGTCS_V101_TIMEOUT_CURRENT_MS | 调整刺激电流 |
| ConfigureStimulationImpedance | EGGTCS_V101_TIMEOUT_STIMULATION_CONFIG_MS | 配置刺激阻抗检测 |
| ConfigureEnvelopeStimulation | EGGTCS_V101_TIMEOUT_ENVELOPE_CONFIG_MS | 包络参数配置 |
| ControlEnvelopeStimulation | EGGTCS_V101_TIMEOUT_ENVELOPE_CONTROL_MS | 包络刺激启停 |

例如将采集控制响应等待时间设为两秒，可改 `V101RequestTimeouts.ControlAcquisition` 为 `00:00:02`，或在启动进程前设置 `EGGTCS_V101_TIMEOUT_ACQUISITION_MS=2000`。它不改变采集时长，也不启用自动重试。

| 网络环境变量 | 默认值与影响 |
|---|---|
| EGGTCS_UDP_BROADCAST_ADDRESS | 255.255.255.255；通用兼容发现入口使用；桌面分模式发现使用相应模式 Address |
| EGGTCS_UDP_LOCAL_ADDRESS | 0.0.0.0；本机绑定/网卡选择 |
| EGGTCS_UDP_DEVICE_PORT | 优先覆盖 DefaultDevicePort；启动默认30307，发现得到的候选端口优先用于该连接 |
| EGGTCS_UDP_CALLBACK_PORT | 30302；本机接收与发现探针声明的回调端口，桌面要求1～65535 |

网络环境变量中的端口采用整数解析：未设置或无法解析时回退默认值；能解析但超出允许范围的值不会因解析成功而成为有效端口，桌面网络配置要求 1～65535。地址变量为空时回退默认地址，非空值直接传入网络层，错误地址可能导致网络校验或连接失败；不会自动改写用户 JSON。超时环境变量与端口变量不同，非空非法值直接报错。所有环境变量须在启动进程前设置。

`ConnectionSource=Simulated` 时，发现与自动连接只使用模拟设备，不探测真实网络；不会用模拟连接覆盖最近真实设备记录或真实网络端口。切回 Real 后仍可恢复最近真实设备。需要真实连接与模拟能力混合时使用 Real 连接来源，并分别设置能力来源。

单刺激言语训练按 `DeviceBackend.Capabilities.Stimulation` 分流包络输出：`Simulated` 使用模拟包络能力，纯模拟及真实连接的混合模式均可正常训练，不要求物理 V102 支持、不发送物理刺激报文，也不暂停真实设备心跳；`Real` 才检查 V102 包络命令支持并下发真实配置；`Disabled` 阻止训练启动，不自动降级为只播放音频。模拟训练同样支持量化电流预览、调试频率和延时调整、重播及停止清理；旧历史模拟数据的载波与调制字段含义不变。

`LastDevice` 默认是 `null`，成功连接后由程序保存对象。其字符串字段 `DeviceId/Model/SerialNumber/MacAddress` 描述身份（后两项可空），`Scheme/Address/ProtocolVersion` 描述候选端点和协议；`DevicePort/LocalPort` 为端口整数，`LocalAddress` 为本机地址。建议由连接流程维护，不手工构造。旧物理记录按 Gen1 兼容来源解析为软件采用的修订，成功连接后写回实际采用值；该记录不代表固件版本探测结果。

当前软件默认采用 Gen1 V102（1.0.2），并保留显式选择 V101（1.0.1）的兼容能力。六条原有命令同时支持两版，包络-tACS 配置与控制仅支持 V102；桌面单刺激言语训练已接入逐句包络下发。协议调试频率范围为 200～1000 Hz；桌面言语训练（含再次训练和复制配置）固定使用 500 Hz，同时控制预览载波，训练页无修改入口。协议修订不是用户 JSON 配置项；旧物理连接记录以兼容来源恢复时采用模块配置修订（默认 V102）。沿用 `V101Protocol`、`V101RequestTimeouts` 和 `EGGTCS_V101_*` 名称。共享 UDP、订阅策略等属于 SDK 代码选项，不是用户 JSON 配置项；不要自行添加，结构同步会删除模板外字段。SDK 不读取桌面 AppData 或环境变量，接入方式见 [通信库跨项目复用说明书](通信库跨项目复用说明书.md)。

## 配置更新、备份与恢复

### 启动同步与版本迁移

#### schemaVersion 的作用与三个存放位置

`schemaVersion` 表示配置文件的结构版本，用于判断旧配置是否需要转换，以及当前程序能否处理这份配置。它不是软件发布版本号，也不是设备协议版本号。

| 位置 | 字段或常量 | 含义 |
|---|---|---|
| 程序代码 `ApplicationConfigurationSynchronizer` | `CurrentSchemaVersion = 2` | 当前程序支持的配置结构版本，是下面两次比较的基准 |
| 程序目录 `appsettings.default.json` | `_meta.schemaVersion`，当前为 `2` | 随程序发布的默认模板采用的配置结构版本 |
| 用户目录 `appsettings.json` | `_meta.schemaVersion` | 这份用户配置当前采用的结构版本；旧文件可能仍为 1，成功迁移后写为 2 |

两个 JSON 文件中的版本号都写在根节点下，例如：

```json
{
  "_meta": {
    "schemaVersion": 2
  }
}
```

这里只展示版本字段，不是完整配置文件。程序中的常量不会因为修改 JSON 而改变。

#### 第一次比较：默认模板版本与程序版本

程序先读取默认模板的 `_meta.schemaVersion`，与代码中的 `CurrentSchemaVersion` 比较。**默认模板版本必须等于程序版本**，不允许向上或向下兼容。

| 默认模板版本 | 程序支持版本 | 比较结果 | 处理 |
|---|---|---|---|
| 1 | 2 | 默认模板低于程序 | 报错并停止启动，提示重新安装当前版本 |
| 2 | 2 | 默认模板等于程序 | 继续读取用户配置 |
| 3 | 2 | 默认模板高于程序 | 报错并停止启动，提示重新安装当前版本 |

这一步检查程序与其随附模板是否配套。程序不会自动迁移默认模板；模板缺失、无法解析或没有有效版本号，也会报错。

#### 第二次比较：用户配置版本与程序版本

默认模板检查通过后，程序读取用户配置的 `_meta.schemaVersion`，仍然与代码中的 `CurrentSchemaVersion` 比较。**这里比较的是用户配置和程序，不是用户配置和默认模板。**

| 用户配置版本 | 程序支持版本 | 比较结果 | 处理 |
|---|---|---|---|
| 未填写版本号（按 0 处理） | 2 | 用户配置低于程序 | 依次执行 0→1→2 迁移 |
| 1 | 2 | 用户配置低于程序 | 执行 1→2 迁移 |
| 2 | 2 | 用户配置等于程序 | 跳过版本迁移，仍执行结构同步和参数校验 |
| 3 | 2 | 用户配置高于程序 | 拒绝启动，要求使用支持该配置的较新程序，不向下迁移 |

例如，安装新版程序后，程序和默认模板都是 2，但用户原来的配置仍为 1，这是正常的升级场景。程序先备份已有用户文件，再按迁移规则转换旧配置，成功后将用户文件的版本写为 2。下次启动时用户配置和程序都为 2，就不会重复执行 1→2 迁移。

如果把采用版本 3 配置的用户目录交给只支持版本 2 的旧程序，程序会拒绝启动，避免旧程序删除或误解新版配置。不能通过把用户文件中的 3 手动改成 2 来解决格式不兼容。

迁移需要程序中存在对应的迁移代码；缺少迁移步骤或迁移失败都会报错，并非只把数字改大就能完成升级。当前 1→2 迁移的实际内容是按电极 Id 为符合条件的旧位置补充三维几何，具体保留规则见下文“电极目录例外”。

#### 版本迁移与结构同步的区别

版本迁移用于执行特定版本之间的数据转换，只在用户配置版本低于程序版本时执行。结构同步则每次启动都会检查，用于补默认字段、移除废弃字段和处理类型不兼容；因此版本相同并不代表跳过所有配置检查。

普通字段新增或删除通常只需更新默认模板。需要保留旧值的字段重命名、移动或语义转换，应由开发者同时更新程序版本常量、默认模板版本，并提供迁移代码。用户配置的版本由程序在迁移后更新，用户不需要手动同步这三个数字。手动将旧用户配置的版本提前改为 2，会让程序跳过本来需要执行的迁移。

#### 完整启动处理顺序

1. 校验当前默认模板存在且 schemaVersion 与程序支持版本一致（当前为 2）。
2. 用户文件存在时读取用户文件；不存在则导入程序目录旧版 `appsettings.json`；两者都不存在则复制当前默认模板。
3. 无版本元数据的旧配置按版本 0 处理，顺序执行 0→1→2 迁移。已有用户文件需要迁移时先备份；用户配置版本高于程序支持版本时则拒绝启动，避免降级程序破坏配置。
4. 按模板同步结构：已有且 JSON 类型兼容的值保留，新增字段补默认值，模板已删除的字段移除；类型不兼容的字段重置为默认值，并记录 `Configuration.TypeReset` Warning。
5. 只有内容发生变化或首次生成时才写文件；已有文件需要变更时先备份，再通过同目录临时文件原子替换。没有变化不重写、不创建备份。
6. 加载并校验实际配置。结构同步不等于数值校验：例如字符串类型的负时间仍可能被保留，但随后校验失败。桌面启动失败处理会尝试恢复启动前用户文件快照、显示错误路径并退出，不静默删除损坏配置；首次生成后校验失败则恢复原先无文件的状态。

普通数组保留用户内容和顺序；对象数组元素按模板结构同步，优先按 `Id` 或 `ElectrodeId` 匹配模板，再按位置或首个对象模板回退。模板默认值为 null 的字段（如 LastDevice）保留用户内容。

**电极目录例外：**已有 `ElectrodePositions.Positions` 数组整体保留，不按模板补齐元素字段、不插入默认电极。升级到版本 2 时，仅对 Id 与默认目录匹配且尚无 `Position3D` 字段的旧位置补充模板三维坐标，并在没有 `Normal3D` 时补充法向。已有自定义三维位置、未知 Id、目录顺序和通道接线保持原样。版本 2 后缺失或无效三维数据不会被普通同步自动修复。

**更新源例外：**`ApplicationUpdate.SourceBaseAddress` 每次同步强制恢复当前默认模板值，加载时再次覆盖为模板值。

新增或删除普通配置字段可由结构同步处理；重命名、移动或改变类型且需要保留原有含义时，开发者应增加 schema 版本并提供顺序迁移。用户不应自行改版本号来代替迁移。

### 应用内保存与生效时间

| 操作 | 保存与生效方式 |
|---|---|
| 字号切换 | 保存 `Display.FontSizePreset` 并即时更新界面资源 |
| EEG 通道映射保存 | 校验后保存映射，后续映射读取使用新值；不代表全部配置热加载 |
| 成功连接设备 | 更新 `DeviceAutoConnection.LastDevice`，供后续自动连接使用；模拟连接不覆盖真实记录 |
| 模拟模式切换 | 修改 DeviceBackend，重启后采用新的服务配置 |
| 手动编辑用户文件 | 下次启动同步、加载后生效 |

这些应用内写入使用配置写入锁和临时文件替换，生产用户配置写入后再次执行结构同步；这不重建所有已加载的服务，也不意味着每次保存都会留下完整历史备份。`config-backups` 的最近 5 份用于同步与恢复流程，不是所有设置操作的撤销历史。

切入模拟模式时，程序先将原配置完整保存到 `appsettings.DeviceBackend.backup.json`，再改为模拟连接与模拟能力。切回时只从备份恢复 DeviceBackend 节，保留切换期间对其他设置的修改，并删除该专用备份。

### 恢复出厂设置与故障处理

设备连接页的“恢复出厂设置”确认后，先备份当前用户配置，再用当前版本默认模板原样覆盖用户文件，删除模拟模式专用备份，并阻止后续配置写入直到重启。操作要求立即重启；失败时会尝试回滚相关文件。它仅恢复配置，不删除数据库、实验数据、采集记录、导出文件或日志。

配置损坏、迁移缺失、版本过高或校验失败时，先根据错误路径检查 JSON 与相应约束。需要恢复备份时退出程序，将选定的兼容版本备份复制为用户 `appsettings.json`，保留原文件供排查，再启动；仍会执行当前版本同步。不要通过删除配置或降低版本号来掩盖错误。

### 耐受度测试

`DeviceBackend.Capabilities.Tolerance` 保留独立来源设置，默认 `Real`；显式设置为 `Simulated` 时使用本地模拟，不访问设备。
设置为 `Real` 时，`Stimulation` 也必须为 `Real`，且所选设备已连接并就绪。
进入耐受度页面会自动下发最低电流配置并启动刺激；离开页面等待设备确认停止。

`ToleranceRun.DurationSeconds` 为真实耐受度测试时长，默认 `600`，范围 `1～65535` 整数秒。
到时结束，不自动重启。调流固定每次 `0.04 mA`，仅按 `0xD1` 回包更新；超时不重发增减指令。
真实模式重置逐档减流，失败或无进展即停止。首次获得设备调流反馈后才可保存真实结果。
