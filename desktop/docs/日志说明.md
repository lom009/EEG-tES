# 日志说明

本文说明桌面程序的日志保存、筛选、轮转与排查方法。日志参数统一位于用户配置的 `SerialLog` 节，配置路径、默认值和修改方式见 [配置文件说明](配置文件说明.md#桌面通信配置与环境变量)。手动修改配置后重启生效。

## 存放位置与记录格式

日志根目录为 `%LocalAppData%\EGGtCSPlatform\logs`，按事件发生时刻对应的电脑本地日期保存：

```text
logs/
  2026-10-15/
    all.1.log
    info.1.log
    warning.1.log
    error.1.log
    bytes.1.log
```

文件按需创建，没有某等级记录就不会创建对应文件。目录不是按程序启动日期划分，排队中的事件即使跨日才写入，也按事件时间归档。

时间戳使用 `yyyy-MM-ddTHH:mm:ss.fffzzz`，包含毫秒与本地时区偏移，使用固定文化格式，不随界面语言变化。例如东八区为 `2026-10-15T16:30:45.123+08:00`，UTC 为 `+00:00`；并非固定输出北京时间。操作、全局异常和 UDP 收发在事件发生时采集时间，写入时保留该时刻并转换为电脑本地时区。UDP 接收日志与接收包共用同一次时间采集，包的 `ReceivedAtUtc` 是同一时刻的 UTC 表示。

### 操作日志

记录格式如下（示意）：

```text
2026-10-15T16:30:45.123+08:00 | Info | ExampleService | Example.Started | id=abc123 | 操作开始
2026-10-15T16:30:45.456+08:00 | Info | ExampleService | Example.Completed | id=abc123 | 操作完成
```

各字段依次为时间、等级、来源、事件名称、关联 ID 和消息。无关联 ID 时显示 `id=-`。消息等单行字段中的换行会转义；带异常的记录在后续行附加异常文本，包括堆栈和内部异常链。因此一条记录可能占多行。

同一次受跟踪操作通常使用相同 ID，以 `.Started` 开始，再记录 `.Completed`、`.Failed` 或 `.Canceled` 结果；取消通常记 Info，失败记 Error。并非所有日志都属于这一操作流程，搜索关联 ID 时也要结合来源、事件名和时间。

记录范围包括启动退出、登录结果、设备连接与断开、实验准备/开始/停止/结果、导出、删除、配置保存与恢复，以及更新检查/下载/重启请求。批量导出记录批次开始与结果汇总，不逐条重复记录内部导出。业务日志不主动记录密码、每次点击或完整业务对象；通信日志会保存原始报文内容。

### 通信日志

UDP 收发仅写入 `bytes.N.log`，格式为：

```text
时间 | TX或RX | 传输名称 | remote=远端端点 | length=字节数 | 完整十六进制字节
```

`TX` 为发送，`RX` 为接收，字节以空格分隔。独立和共享 UDP 路径均可产生日志；桌面当前采用独立 UDP。`bytes` 是诊断用收发记录，不是 EEG 采集文件，也不能替代可靠的完整抓包。

## 等级、开关与文件分流

| 等级 | 文件 | 常见用途 |
|---|---|---|
| Trace | `trace.N.log` | 最细粒度诊断 |
| Debug | `debug.N.log` | 连接重试等调试细节 |
| Info | `info.N.log` | 正常操作开始、结果和取消 |
| Warning | `warning.N.log` | 登录拒绝、连接异常、配置类型重置等 |
| Error | `error.N.log` | 操作失败、非终止性全局异常 |
| Fatal | `fatal.N.log` | 终止程序的未处理异常 |

操作记录同时写入对应等级文件和 `all.N.log`。`all` 只汇总通过等级筛选的操作日志，不包含 `bytes`，也不绕过筛选。

| SerialLog 参数 | 默认值 | 行为 |
|---|---|---|
| `Enabled` | `true` | 操作与通信文件日志的共同开关 |
| `MinimumLevel` | `Trace` | 保留该等级及更高等级；不影响 bytes |
| `MaxFileSizeBytes` | `10485760`（10 MiB） | 每类文件各自的分片大小阈值，须为正数 |
| `RetentionDays` | `30` | 包含当天的自然日保留数，允许 1～36500 |

例如设置 `MinimumLevel=Warning` 后，Info 和 Debug 不会出现在等级文件或 all 中，但仍会产生 bytes。当前没有独立的“只关闭 bytes”配置开关。等级文件与 all 会重复保存同一操作记录，大小阈值也不是所有日志的总磁盘空间上限。

## 分片、清理与旧版文件

每个日期、每类文件的序号从 1 开始。同日重启按数值寻找最大序号并续写，历史文件不重命名，已有序号空缺不补齐。写入新记录前，若当前文件已达阈值，或追加后将超过阈值，则创建下一片。

单条记录不会为了满足大小限制而拆开：一条记录本身超过阈值时仍完整写入一个文件，允许该文件超限，下一条再进入新分片。阈值按实际 UTF-8 写入字节数（含换行）计算。

日志启用时，成功读取用户日志配置后触发保留清理；跨日后的下一次日志写入也会检查清理。它不是午夜定时任务，无新写入时不保证午夜立即删除。默认 30 天保留当天和前 29 天，例如本地日期为 2026-10-15 时保留 2026-09-16 及之后的日期目录中的日志。关闭日志时不执行保留清理。

清理只处理严格匹配 `yyyy-MM-dd` 的过期目录中已识别的正整数序号日志分片：all、六个等级和 bytes。清理后目录为空才删除；未知文件、其他目录格式和重解析点会跳过。旧版 `BytesLog.log`、`error/Error.log` 不迁移、不自动删除。保留天数不能保证整个日志根目录低于某个容量。

## 异步写入、异常与退出

操作日志和通信日志分别进入独立的无界队列，由后台消费者写文件，每次文件追加后执行 Flush。二者没有全局严格写入顺序，排查时应按事件时间和关联 ID 对照。文件操作使用命名互斥量协调，等待上限为 2 秒；获取失败可能导致本次写入跳过。

通信进入文件日志队列前，还经过容量为 **2048** 的分发队列；满时丢弃最旧记录，以免日志阻塞通信。因此 bytes 不保证完整，磁盘变慢、队列拥塞或进程退出都可能使记录缺失。无界文件队列也不代表落盘速度无限或异常退出时不丢记录。

一个日期下某类输出失败时，暂停该输出路径的后续写入，其他输出仍继续。例如 error 写失败不必然影响 all 或 bytes。下次日期维护（跨日，或日志保留天数发生变化）会清除失败标记并允许重试；并非每条记录都立即重试。维护或写入错误使用 `Debug.WriteLine` 后备输出，不递归写文件日志，这些诊断可能仅在调试输出中可见。Flush 完成也不等于所有失败记录已成功保存。

程序在读取配置前先用默认日志参数启动，但推迟历史清理，避免尚未读取用户保留天数就删除日志。配置加载成功后切换为用户参数，因此即使 `Enabled=false`，也可能留下早期启动记录；已经入队的记录保留入队时的日志参数。

正常退出先完成业务收尾和服务释放，再记录最终退出事件、关闭队列并等待写入结束，最多等待 5 秒。全局异常按是否终止程序记录 Error 或 Fatal，并请求刷新。强制结束进程、断电或等待超时都无法保证最后的记录完整。

崩溃机制还会另存 `%ProgramData%\EGGtCSPlatform\lastcrash.json`，它与按日文件日志是不同机制，不受日志分片和保留天数管理。`Application.ShowPreviousCrashOnStartup` 控制是否在下次启动显示上次崩溃信息；不等于关闭崩溃记录本身。

## 常见排查步骤

| 现象 | 检查顺序 |
|---|---|
| 找不到日志 | 确认运行程序的 Windows 用户及 LocalAppData 目录；检查事件本地日期、Enabled、MinimumLevel，以及是否确实发生过对应事件；再检查目录权限和磁盘空间 |
| 缺少 Debug/Info | 检查 MinimumLevel 并重启；all 也会过滤，不能从 all 找回被过滤记录 |
| all 中找不到报文 | 查看同日期 bytes 分片；all 不汇总通信字节 |
| 通信记录不完整 | 对照所有 bytes 分片与操作时间；检查队列拥塞、写入故障和异常退出，不能仅凭缺失日志认定设备未收发 |
| 文件超过大小限制 | 检查是否为单条超大记录；阈值不拆分记录，也不限制目录总量 |
| 旧文件未删除 | 核对本地日期、保留天数、日志是否开启及是否触发维护；旧版和未知文件不会自动删除，含未知文件的目录也会保留 |
| 修复权限后仍无某类记录 | 该输出可能已标记失败；排除目录或磁盘故障后重启，或等待下一次日期维护重试 |
| 关闭日志后仍有少量记录 | 检查是否为配置加载前的启动记录，或切换参数前已入队记录；手动改文件需重启 |
| 没有最终退出记录 | 核对等级过滤、写入故障、退出等待超时以及是否强制结束进程 |
