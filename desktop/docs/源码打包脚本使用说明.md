# 源码打包脚本使用说明

[`scripts/Pack-Source.ps1`](../scripts/Pack-Source.ps1) 将当前工作区的源码打包为 ZIP，便于分享或交接。它读取文件在磁盘上的当前内容，因此包含尚未提交的修改，不是仅导出最新提交。

## 1. 运行环境

- Windows PowerShell 5.1 或 PowerShell 7。
- 已安装 Git，且当前终端可以执行 `git`。
- 项目保留可用的 Git 仓库信息；脚本依赖 Git 获取文件清单，不能直接用于没有 Git 信息的源码解压目录。

打包不执行构建，无需先运行 `dotnet build`。

## 2. 使用方法

以下命令均在仓库根目录的 PowerShell 终端中执行。

使用默认输出路径：

```powershell
.\scripts\Pack-Source.ps1
```

指定绝对路径，路径包含空格时用引号包裹：

```powershell
.\scripts\Pack-Source.ps1 -OutputPath 'D:\Shared Sources\EGGtCSPlatform.zip'
```

指定相对路径：

```powershell
.\scripts\Pack-Source.ps1 -OutputPath '.\artifacts\source\source-review.zip'
```

也可以显式选择 PowerShell 运行：

```powershell
# Windows PowerShell 5.1
powershell -File .\scripts\Pack-Source.ps1

# PowerShell 7
pwsh -File .\scripts\Pack-Source.ps1
```

## 3. 参数与输出

脚本唯一的业务参数如下：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `-OutputPath` | 字符串 | 否 | ZIP 输出文件路径。省略、传入空字符串或纯空白时使用默认路径。建议以 `.zip` 结尾。 |

默认输出路径相对于项目根目录：

```text
artifacts/source/EGGtCSPlatform-source-yyyyMMdd-HHmmss-fff.zip
```

文件名中的时间戳表示运行时的本地日期和时间，精确到毫秒，例如 `EGGtCSPlatform-source-20260930-153045-123.zip`。

项目根目录由脚本所在的 `scripts` 目录的父目录确定。自定义的相对输出路径则基于**调用者当前所在目录**解析，不是基于脚本目录；从其他目录调用时应留意这一差异。

脚本会自动创建输出父目录，但不会覆盖已有文件。如果目标路径已存在，打包立即失败；即使其他进程在检查之后创建同名文件，脚本也不会覆盖它。

ZIP 内保留文件相对于项目根目录的路径，顶层目录固定为 `EGGtCSPlatform/`，不随输出文件名或本地仓库文件夹名称变化。例如：

```text
EGGtCSPlatform/
  scripts/
    Pack-Source.ps1
  docs/
    源码打包脚本使用说明.md
  ...
```

成功后终端会显示以下字段：

| 字段 | 含义 |
| --- | --- |
| `Archive` | ZIP 文件的完整输出路径。 |
| `Files` | 实际写入 ZIP 的文件数量。 |
| `Size` | ZIP 文件大小，同时显示 MB 和字节数；这里的 MB 按 `1 MB = 1,048,576 bytes` 计算。 |

## 4. 文件收录规则

脚本在项目根目录执行以下 Git 命令获取候选文件：

```powershell
git ls-files --cached --others --exclude-standard -z
```

收录规则如下：

- 包含 Git 已跟踪且磁盘上仍存在的文件，使用当前磁盘内容，包含已暂存和未暂存修改后的最终工作区内容。
- 包含未被 Git 忽略的未跟踪文件，因此新建文件无需先提交即可打包。
- 跳过磁盘上已不存在的文件，并对候选路径去重。
- 已跟踪文件即使命中忽略规则，仍会收录；忽略规则只用于筛选未跟踪文件。
- 不包含 Git 历史和 `.git` 元数据，也不保留暂存区与工作区之间的差异。
- 只写入文件，不单独保留空目录；遇到仍存在的子模块目录等非普通文件 Git 条目时会报错，不会递归打包子模块。

未跟踪文件的忽略规则由 Git 决定，包括仓库 `.gitignore`、`.git/info/exclude` 和适用的全局忽略配置。当前仓库忽略了 `bin/`、`obj/`、`artifacts/`、`Publish/`、测试产物、IDE 本地状态、日志和临时文件等；这些内容在未跟踪时不会打包。`.env` 和 `.env.*` 也被忽略，但 `.env.example` 是例外。

默认输出目录 `artifacts/source/` 已被忽略，通常不会把此前生成的源码包再次打进去。若把输出放在仓库中未被忽略的其他目录，后续运行可能收录此前生成的 ZIP；建议使用默认目录或仓库外的目录。

## 5. 常见问题

| 现象或错误 | 原因与处理 |
| --- | --- |
| 找不到 `git` 命令 | 安装 Git 并确保其位于 `PATH` 中，重新打开终端后用 `git --version` 检查。 |
| `Git could not list source files: ...` | Git 无法读取文件清单。根据附带的 Git 错误检查仓库信息、访问权限等；可在项目根目录运行 `git status` 辅助定位。 |
| `Output already exists: ...` | 输出路径已存在。改用新文件名，或省略 `-OutputPath` 使用带时间戳的默认名称。 |
| `No source files were found to package.` | 筛选后没有可打包文件。检查工作区文件是否存在，以及新文件是否全部被忽略。 |
| `Cannot package a non-file Git entry (for example, a submodule): ...` | 文件清单中出现仍存在的子模块目录等非文件条目。当前脚本不支持此类条目，需要使用支持子模块的打包方案。 |
| 创建目录、读取文件或写入 ZIP 失败 | 检查输出目录权限、磁盘空间，以及源文件是否被占用或在打包期间被删除。 |

若在 ZIP 创建或写入阶段发生异常，脚本会关闭已打开的压缩包和文件流，并尝试删除本次创建的不完整 ZIP 后抛出错误。它不会删除此前已存在的目标文件；已创建的父目录可能保留。如果清理操作也因权限等原因失败，应检查输出位置是否残留不完整文件。
