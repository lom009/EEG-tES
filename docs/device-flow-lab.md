# 上位机—下位机流程实验室说明

## 目的

`/?screen=device-lab` 用于在没有真实刺激器和 EEG 设备时，验证上位机的产品流程、协议编译、前置校验、状态机和事件记录。

当前页面不是医疗设备控制软件，也不输出任何真实安全结论。所有阻抗、耐受和 EEG 数据均为模拟值。

## 分层

1. **上位机语义协议**
   - 刺激范式：tDCS、tACS、TI。
   - 阵列拓扑：Bipolar、4×1 HD、多通道、TI 双回路。
   - 电极点位、硬件通道、发生器分组和电流方向。
2. **设备适配器**
   - 页面只依赖统一的适配器方法，不依赖某个厂商 SDK。
   - 当前实现为 `DemoDeviceAdapter`。
   - 未来可替换为厂商 SDK、串口、USB 或 BrainFlow 采集适配器。
3. **模拟下位机**
   - 校验并接收 PREPARE 程序。
   - 按顺序执行耐受确认、阻抗检测、ARM、START、ABORT。
   - 回传带序号、来源和时间戳的设备事件。
4. **数据与事件流**
   - 模拟 EEG 数据包用于验证订阅、刷新和时间戳。
   - 操作者标记、刺激段开始、完成和急停均进入同一事件序列。
   - 真机阶段如需跨设备时间同步，可将数据与标记发布到 LSL。

## 当前可跑通流程

1. 选择模拟设备能力并连接。
2. 可选启动合成 EEG 数据流。
3. 选择 tDCS、tACS 或 TI；不支持的范式由设备能力清单禁用。
4. 选择刺激阵列并填写波形参数。
5. 生成电极与硬件通道映射。
6. 上位机静态校验并编译为下位机可执行程序。
7. 下发 PREPARE，等待模拟下位机确认。
8. 先完成耐受确认，再检测刺激阻抗。
9. ARM 后 START；运行中可 ABORT。
10. 查看 EEG 数据包、设备事件、实验标记和最终状态。

## 采用的开源产品思路

- **BrainFlow**：借鉴“统一板卡接口 + 模拟板卡”的设备抽象，不直接引入其原生依赖。
- **Lab Streaming Layer（LSL）**：借鉴数据流与实验标记使用统一时间线的方式；当前仅为本地事件模型，并非真实 LSL。
- **OpenBCI GUI**：借鉴连接、实时数据、事件和记录分层呈现的上位机结构。
- **SimNIBS**：后续可作为刺激方案的电场仿真与规划工具，不承担实时设备控制。
- **MNE-Python**：后续可用于标准电极坐标、EEG 数据结构和离线分析。

## 真机接入前仍需完成

- 厂商协议、USB/串口断线恢复、心跳和超时重试。
- 上下位机双向协议版本协商及配置哈希确认。
- 真实阻抗量程、测量错误、过流、开路和短路处理。
- 硬件急停、看门狗、联锁和掉电安全策略。
- EEG 丢包、缓存、时钟漂移与 LSL 对时。
- 医疗器械风险管理、可用性工程、软件生命周期和验证记录。
