# EEG-tES 虚拟下位机与真实数据仿真落地计划

> 版本：v1.2  
> 日期：2026-07-28  
> 目标：在缺少真实下位机的条件下，使产品流程、通信协议、状态机、时序、数据结构、异常处理、存储与回放尽可能接近真实系统；明确区分模拟数据与真实生理/硬件数据。

## 1. 最终目标

完成一套可替换数据源的上位机架构：

```text
产品页面
  └── DeviceSession 统一会话
        ├── AcquisitionAdapter 采集数据面
        │     ├── Virtual / Replay / Real gateway
        └── StimulationAdapter 刺激控制面
              ├── Virtual / Real device
```

完成后应满足：

1. 产品页面不再自行生成 EEG、阻抗、计时或设备状态。
2. 页面只发送设备命令、消费设备事件。
3. 模拟实验可以按相同 seed 完整复现。
4. 正常、异常、急停、断连、重试等流程都有可重复测试场景。
5. 每次实验产生独立、可校验、可回放的数据包。
6. 真实设备到位后，只新增对应采集网关或刺激设备适配器，不重写业务流程。

采集与刺激必须拆成两个数据面：EEG/采集阻抗是高频连续数据，刺激是低频高安全等级控制。二者通过 `runId`、设备单调时间和 marker 对齐，不要求由同一硬件或同一传输协议提供。

## 2. 真实性边界

| 数据或能力 | 当前可达到的程度 | 对外口径 |
|---|---|---|
| 患者、操作者、实验 ID | 真实生成、关联和持久化 | 真实业务数据结构 |
| 刺激方案、点位、参数 | 真实配置、校验和版本化 | 真实产品配置 |
| 状态机、门禁、计时 | 真实运行 | 真实软件行为 |
| 命令、事件和错误码 | 按设备协议运行 | 协议级仿真 |
| EEG、阻抗和设备反馈 | 可重复的高拟真生成 | 模拟数据 |
| 实际刺激电流输出 | 无法实现 | 不得称为真实输出 |
| 患者生理反应 | 无法实现 | 不得称为真实反应 |
| 固件和电气安全特性 | 仅能按假设模拟 | 待真实设备验证 |

### M3：阻抗与 EEG 仿真

> 当前进度（2026-07-28）：M3 已完成。虚拟采集端以固定
> `scenarioId + seed` 连续生成带通道差异的 EEG 包，包含 Alpha/Theta/Beta、
> 50 Hz 工频、基线漂移、眨眼、肌电和刺激伪迹；采集与刺激阻抗均输出
> `MEASURING → PASSED/FAILED` 动态帧。页面明确标注模拟信号模型版本，
> 高通、低通和陷波仅处理显示副本，不改写设备原始帧。患者级信号画像、
> 确定性丢包、传输延迟和设备时钟漂移均可通过 scenario 配置并复现。
> 运行中电极异常作为安全故障进入 M4。

#### M3 场景参数

| 参数 | 含义 | 默认值 |
|---|---|---:|
| `patientSignalProfile` | 患者/会话级节律、工频及伪迹强度配置 | 由患者 seed 确定性生成 |
| `packetLossEveryN` | 每 N 个采集包模拟丢失一次；0 表示关闭 | `0` |
| `packetLatencyMs` | 数据包从生成到上位机收到的模拟延迟 | `0 ms` |
| `clockDriftPpm` | 下位机设备时钟相对虚拟主时钟的漂移 | `0 ppm` |

丢失的数据包仍推进设备采样索引，但不会生成替代波形；模拟器输出
`ACQUISITION.PACKET_DROPPED`，下一份成功交付的 EEG 帧通过
`droppedSamplesBefore` 明确报告缺口。帧同时记录生成/交付设备时间、
模拟延迟、采样周期、信号画像 ID 和时钟漂移，供上位机验证连续性。

#### 采集来源与网关边界

M3 不把产品绑定到某个串口实现。参考 OpenBCI GUI、LSL 和 EEGsynth/FieldTrip
的接入方式，采集侧先固定 `AcquisitionAdapter` 契约，再逐步支持
`VIRTUAL / REPLAY / LSL / FIELDTRIP / DIRECT_DEVICE` 数据来源。

OpenBCI 文档中的 `monopolar / bipolar` 属于采集参考拓扑，不作为刺激阵列命名。
具体设备通道数、采样率和传输特性须由目标型号与固件 capability 确认。
详细记录见 [OpenBCI 采集接入参考](./openbci-acquisition-reference.md)。

#### 阻抗模型

每个电极独立维护：

- 基础阻抗。
- 缓慢漂移。
- 接触噪声。
- 偶发跳变。
- 运行中脱落状态。
- 刺激与采集检测阶段的不同事件频率。

#### EEG 模型

最低包含：

- Alpha、Theta、Beta 等基础节律。
- 通道间相关性与独立噪声。
- 50 Hz 工频干扰。
- 基线漂移。
- 眨眼、肌电、运动伪迹。
- 刺激期间的刺激伪迹。
- 指定采样率下连续输出与分包。

| 项目 | 内容 |
|---|---|
| 工作 1 | 建立患者/会话级信号参数，避免每个通道完全相同 |
| 工作 2 | 500 Hz 多通道连续采样和分包 |
| 工作 3 | 动态阻抗帧和检测结果 |
| 工作 4 | 显示滤波作用于副本，原始数据保持不变 |
| 工作 5 | 加入丢包、延迟和时钟漂移参数 |
| 交付物 | 可配置数据生成器、信号场景、阻抗场景 |
| 完成标准 | 时长、采样点数、通道数、序列号和时间戳相互一致；无静默断帧 |

### M4：故障与安全状态

| 故障 | 预期软件行为 |
|---|---|
| 高阻抗 | 阻止准入，显示具体通道和原因 |
| 电极运行中脱落 | 记录异常并按场景进入警告或中止 |
| 设备断开 | 冻结运行状态，禁止继续下发 |
| 数据包丢失 | 记录缺口，不伪造为真实采样 |
| 时间戳回退 | 拒绝异常帧并记录时钟错误 |
| capability 不匹配 | 阻止方案 PREPARE |
| 紧急停止 | 立即进入中止状态，冻结数据并生成结果 |
| 自动模式重新开始 | 新建 runId，从第一阶段完整重跑 |

完成标准：

- 每种故障具有固定 scenario 和 seed。
- UI、事件日志与结果文件对故障原因描述一致。
- 不允许中止实验被记录为正常完成。

当前实现（v0.5.0）：

- 工作流原型支持通过 URL 选择确定性故障场景，未指定时仍运行正常流程：
  - `fault=electrode-warning`：运行中电极接触恶化，仅警告并继续采集；
  - `fault=electrode-abort`：运行中电极脱落，立即进入安全中止；
  - `fault=disconnect`：模拟传输断开，采集和刺激均断开并冻结结果；
  - `fault=clock-rollback`：拒绝时间戳回退帧并中止运行。
- 高阻抗会在界面显示具体电极和阻抗值；capability 不匹配会在
  `PREPARE` 阶段被拒绝。
- 故障原因使用同一错误码写入设备协议日志、操作事件、运行结果和结果详情。
- 紧急停止后的旧运行不会产生完成事件；自动模式重新运行时会生成新的
  `runId` 并从第一阶段开始。
- `scripts/verify-virtual-device-faults.mjs` 覆盖警告、中止、断连、时钟回退、
  capability 不匹配、紧急停止与重新运行；丢包和高阻抗继续由 M3/设备流程
  回归脚本覆盖。

| 项目 | 内容 |

| 工作 1 | 定义 Run Bundle 版本和字段 |

| 工作 3 | 实现 ReplayDeviceAdapter |
| 工作 4 | 回放支持暂停、倍速和跳转，但保持原始设备时间 |
| 工作 5 | 导出时明确标注 `SIMULATED / REPLAY / HARDWARE` |

#### 当前实现（v1.0）

- 已实现单文件可移植容器 `EEG_TES_RUN_BUNDLE_PORTABLE_V1`，同时保留目录包的
  逻辑文件边界。
- EEG 原始帧使用 Float32 little-endian、channel-major 编码，设备时间、采样率、
  通道顺序和帧索引独立保存。
- 每个逻辑文件写入长度和 FNV-1a 32 位校验；该校验用于发现演示文件损坏，
  不是密码学签名。
- `ReplayDeviceSession` 支持手动/实时两种模式、暂停、继续、倍速与时间轴定位；
  回放倍速不改写原始设备时间。
- 工作流原型可导出当前模拟运行，并从本地导入回放；回放事件和帧统一标记为
  `REPLAY`，同时保留原始 `SIMULATED` 来源。
- 格式、字段和操作说明见 [Run Bundle v1.0](run-bundle-v1.md)。
- `scripts/verify-run-bundle.mjs` 覆盖确定性序列化、校验失败、EEG 二进制还原、
  回放暂停/继续、倍速、定位和完成状态。

## 5. 关键依赖与关键路径

```text
M0 基线
  → M1 契约
      → M2 虚拟设备状态机
          → M3 数据仿真
              → M4 故障场景
                  → M5 保存与回放
                      → M6 验收
```

M1 是最关键的硬依赖。M1 未稳定前，不应大规模制作 EEG、阻抗或结果数据。

## 6. 优先级控制

### Must have

- DeviceAdapter 单一边界。
- 确定性 seed。
- 手动/自动完整状态机。
- 动态阻抗和连续 EEG。
- 急停、断连、高阻抗。
- 设备事件日志。
- 模拟数据来源标识。

### Should have

- Run Bundle。
- Replay 模式。
- 丢包、延迟和时钟漂移。
- 原始数据与显示滤波数据分离。

### Could have

- 更多患者信号模型。
- 可视化场景编辑器。
- EDF/BDF 标准格式导出。
- 性能压测与长时运行。

### 本阶段不做

- 声称具备真实电流输出。
- 声称具备医疗器械安全认证。
- 用模拟数据推断患者生理疗效。
- 在没有真实协议前写死串口字节格式。

## 7. 风险矩阵

| 风险 | 概率 | 影响 | 等级 | 缓解措施 |
|---|---|---|---|---|
| 下位机协议未知 | 高 | 高 | 高 | 业务契约与传输层分离；真实串口格式后置 |
| 产品流程继续变化 | 高 | 中 | 高 | 状态机和页面结构解耦 |
| 模拟数据被误认为真实数据 | 中 | 高 | 高 | 全链路写入数据来源和模拟版本 |
| EEG 看起来像装饰波形 | 中 | 中 | 中 | 引入频谱、伪迹、通道相关和连续时间 |
| 长时间运行浏览器内存增长 | 中 | 中 | 中 | 环形缓冲、分块落盘、性能监控 |
| 参数范围缺少硬件依据 | 高 | 高 | 高 | 所有范围来自 capability，标注待设备确认 |
| 患者隐私风险 | 中 | 高 | 高 | 当前仅用合成/去标识数据 |

## 8. 每个里程碑的验收指标

| 里程碑 | 核心指标 | 护栏指标 |
|---|---|---|
| M1 | 100% 设备动作有命令或事件定义 | UI 文案不进入协议字段 |
| M2 | 相同 seed 的事件摘要 100% 一致 | 页面不直接生成设备状态 |
| M3 | 采样点数误差为 0；时间戳单调 | 原始数据不被显示滤波覆盖 |
| M4 | 8 个核心场景均得到预期终态 | 中止不得写为完成 |
| M5 | 数据包可完整回放 | 模拟来源不可丢失 |
| M6 | 虚拟与真实适配器使用同一契约测试 | 无真实设备时不宣称硬件验证通过 |

## 9. 执行与变更规则

1. 严格按 M0 → M6 推进，每个阶段验收后再进入下一阶段。
2. 任何新增页面需求先判断是否改变设备契约；不改变契约的需求不得阻塞模拟器。
3. 每周只集中调整一次协议，避免命令和事件持续漂移。
4. 每个 P0 新需求必须说明替换或推迟哪个现有任务。
5. 每个阶段保留 15%—20% 缓冲，不把估算排满。
6. 实现改动按项目规则保存在本地；仅在用户明确要求“同步 GitHub”时提交和推送。
