# 包络 tACS 单刺激自动化验收矩阵 V0.1

## 1. 范围与依据

- 范围：单刺激模式中的包络 tACS，从新建实验到结果查看；不包含 EEG 采集，也不验收模拟模式的启用方式。
- 产品逻辑依据：[页面交互流程图 V1.0](./包络tACS单刺激页面交互流程图_V1.0.md)。
- 视觉样式基准：[Figma「单刺激（包络）」页面](https://www.figma.com/design/1sFpUX3GlXOiFhODJu8GRK/EEG-tES-?node-id=555-12471)，用于验收静态页面的布局、尺寸、间距、颜色、字体、图标、组件状态和整体视觉效果。
- 现有产品规则补充：实验必须引用适用且已完成的耐受记录；刺激方案或刺激点位修改后，旧刺激阻抗结果失效；电极页不重复配置刺激参数。
- 流程、文案、门禁、动态行为和时间关系按流程图 V1.0。Figma 作为视觉样式基准；只排除设计稿中的示例患者、实验编号、参数数值、阻抗、时间和评分数据。差异记录在本文件第 4 节。

验收执行使用独立的测试患者、耐受记录、语料及模拟设备数据。每次运行记录应用版本、系统与窗口尺寸、测试数据编号、操作轨迹、截图及状态断言结果。

判定方式：**规则**为可重复的状态或数据断言；**视觉**为实际截图与 Figma 静态样式基准的比对；**体验**为 AI 提出带操作证据的待评审问题。严重程度按偏差影响判定，不预先降低视觉问题等级；头模与点位不移动等明确规则按 P0 判定。

## 3. 视觉样式验收规则

1. 在与 Figma 相同的 1440×900 画面尺寸下采集应用截图，固定显示缩放和字体环境。对静态界面进行像素差异与元素几何比对，逐项核对布局、尺寸、间距、颜色、字体、图标、边框、阴影、按钮和禁用态。
2. Figma 中的患者、实验编号、参数数值、阻抗、时间和评分仅是示例数据：像素比较时只遮罩这些文字或动态图形的内容，保留其容器、位置和文字样式检查；实际数据正确性由流程规则及固定测试数据断言。
3. 头模尺寸、位置和点位坐标同时对照 Figma 电极画面与产品规则；切换角色或检测状态时，再用同一次运行中的跨状态截图确认它们没有移动或缩放。
4. 运行中波形的实时内容按流程图 V1.0 检查揭示进度；Figma 用于比对坐标网格、曲线颜色和线条样式。以 `0`、`D`、音频结束 `T`、刺激结束 `T+D` 的可控时间检查轨道是否为空、揭示范围和游标进度。
5. 视觉差异报告必须给出 Figma 节点、应用截图、差异区域和量化结果；AI 可解释差异并归类，产品或设计人员复核有争议的结论。精确门禁、时间关系及数据一致性由程序判定。

## 5. 可复用验收框架的产品接入契约

通用引擎负责场景执行、等待条件、截图／可访问性树／状态证据采集、视觉样式评估、AI 问题归纳和报告生成。每个新产品提供以下五种配置：

1. **产品规则包**：页面状态、门禁、失效条件及严重程度。
2. **设计映射包**：Figma 节点或其他已批准视觉基准、关键截图区域，以及只排除示例数据内容的动态遮罩。
3. **场景包**：前置数据、用户动作、检查点、预期结果。
4. **测试数据适配器**：创建与清理隔离数据、模拟外部设备或服务、控制时间与失败分支。
5. **界面驱动适配器**：Avalonia/macOS、Windows、Web 或移动端的启动、定位、点击、输入和截图实现。

场景定位优先使用稳定的语义标识；屏幕坐标仅用于无法暴露语义节点的画布操作。一次验收结果至少包含：产品版本、场景 ID、步骤轨迹、预期与实际、截图／录屏、失败规则、复现信息和人工复核状态。

## 6. 实施顺序

1. 固定测试数据、主要截图检查点和 Figma 视觉基准；D-03、D-05 的产品呈现细节作为待评审项记录，不阻塞已明确的流程规则测试。
2. 先自动跑通 SS-01～SS-11 的主路径，再加入 SS-12～SS-15 的异常、评分与结果检查。
3. 首轮通过真实 macOS 应用及其可访问性树执行。仓库现有 `VisualTests` 可复用截图场景，但当前在此 Mac 上报 Avalonia Native `RenderTimer -6661`，需另行修复后才能纳入自动门禁。
4. 用首份报告评估误报、漏报和证据是否足以复现，再将场景格式与适配器抽出供其他产品使用。
