# 旧版 bci-demo 项目分析

## 1. 项目定位

`bci-demo` 是 EEG+tES 实验配置流程的前端交互原型，覆盖从新建实验到电极点位配置、阻抗检查和刺激参数设置的核心体验。它目前是纯前端演示，没有后端接口、账号系统、设备通信或数据持久化实现。

旧项目位置：`/Users/fengyinan/Downloads/bci-demo`

设计来源：Figma 文件 `1sFpUX3GlXOiFhODJu8GRK`，主节点 `1:2`，新建实验页节点 `8:1305`。

## 3. 已实现功能

### 新建实验

- 展示实验 ID 与日期。
- 输入被试 ID，空值进入下一步时显示错误状态。
- 填写可选备注。
- 通过原生文件选择器导入 `.expp` 参数包；当前仅保留文件对象，不解析内容。
- 进入“电极配置”后返回，表单状态仍然保留。

### 电极配置与阻抗检查

- 提供 20 个 10–20 系统点位：FP1/FP2、F7/F3/Fz/F4/F8、T3/C3/Cz/C4/T4、T5/P3/Pz/P4/T6、O1/Oz/O2。
- 点位可分配为采集电极或刺激电极。
- 刺激电极支持阳极 A、阴极 C。
- 再次点击相同配置会取消点位；切换角色会替换原配置。
- 已选点位同步显示为可删除标签。
- 下发配置后生成演示阻抗值和优/良/中/差/不良状态。
- 阻抗复检使用 700 ms 定时器模拟，并轻微调整显示值。
- 当 Pz 为刺激点、P4 为采集点时，显示固定的距离冲突警告。
- 存在大于 10 kΩ 的结果时，显示补充导电膏提示。

### 刺激参数

- 支持 tDCS、tACS、TI、HD 四种模式切换。
- 提供模式对应的波形预览、滑块和数值输入。
- TI 支持 A/B 通道载波频率和电流，并计算干涉频率与包络电流。
- HD 支持默认电流批量应用及 7 通道独立电流设置。
- 所有参数只保存在当前页面内存中，没有校验协议、设备下发或保存能力。

## 4. 关键代码现状

### 当前实际使用静态头模

`App.jsx` 当前通过 `head-static.png` 展示头部，并在图片上覆盖 HTML `button` 作为电极点位。这是当前可见页面真正采用的实现。

### Three.js 组件存在但未挂载

`HeadModel.jsx` 已实现：

- 加载 `head.glb`；
- WebGL 光照与半透明材质；
- CanvasTexture 电极标签；
- 射线拾取点位；
- 水平/垂直最大 ±35° 拖动旋转；
- 双击复位；
- ResizeObserver 自适应；
- 完整的纹理、材质、几何体、控制器和渲染器清理。

但 `App.jsx` 没有导入或渲染 `HeadModel`。因此旧 `AGENTS.md` 中“中央画布使用 Three.js 加载头模”的描述与当前代码不一致。迁移前需要先决定以静态高保真实现还是可交互 3D 实现为产品基线。

## 5. 原型限制与风险

- 业务数据均为硬编码演示数据，包括实验 ID、日期、阻抗值和距离冲突规则。
- `.expp` 文件没有格式定义、解析、校验或错误处理。
- 没有与 EEG/tES 硬件、采集服务或刺激设备通信。
- 没有路由、持久化、后端 API、权限和审计日志。
- 阻抗复检是定时器模拟，不代表真实测量状态机。
- 主要逻辑集中在单个 `App.jsx`，继续扩展会增加维护成本。
- 全局 CSS 体积较大，组件间样式边界较弱。
- 3D 头模与页面状态没有完成双向集成；组件内部点位状态和 `App` 状态是两套模型。
- 仅有人工设计 QA 记录，缺少单元、交互、视觉回归和端到端测试。
- `dist/` 是旧构建产物，不应作为后续开发源文件。

## 6. 建议迁移顺序

1. 明确产品基线：确定使用静态头模还是 Three.js 交互头模。
2. 将旧源码和必要资产迁入新仓库，排除 `dist/`、临时对比图和本机绝对路径。
3. 拆分页面与领域组件：实验表单、电极地图、角色配置、阻抗面板、刺激参数面板。
4. 建立统一领域模型：实验、被试、电极分配、阻抗测量、刺激协议和设备状态。
5. 定义 `.expp` 文件格式与版本策略，并实现导入校验。
6. 把硬编码测量与下发逻辑替换为明确的设备/API 适配层。
7. 增加输入边界、安全限制、刺激参数联动校验和错误恢复流程。
8. 补充自动化测试和 1440 × 900 基准视觉回归。
9. 完成无障碍、响应式布局和浏览器兼容性验证。
