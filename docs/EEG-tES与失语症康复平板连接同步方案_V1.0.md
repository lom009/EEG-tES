# EEG-tES 与失语症康复平板连接同步方案 V1.0

> 文档版本：V1.0-draft  
> 更新日期：2026-08-24  
> 文档性质：产品方案 / 系统连接与数据同步设计  
> 适用范围：EEG-tES 上位机、失语症康复训练平板、联合结果分析服务  
> 当前状态：用于产品、研发、算法、硬件与临床团队评审，不代表最终医疗协议或注册方案

## 1. 一句话结论

EEG-tES 与失语症康复平板保持为两个独立产品，通过同一局域网建立一次联合康复会话。EEG-tES 上位机负责实验身份、设备安全门禁和统一启动；平板负责康复任务和行为记录；平板产生的题目、提示和回答事件实时写入 EEG 时间轴，最终落到具体 EEG 采样点。两端不得依赖治疗结束后人工对时间完成任务级数据匹配。

推荐总体结构：

```text
                         ┌────────────────────────┐
                         │ 联合结果分析 / Agent   │
                         │ 质控、比较、解释、报告 │
                         └───────────▲────────────┘
                                     │ 联合数据
                                     │
┌──────────────────┐   局域网连接   ┌┴─────────────────────┐
│ 失语症康复训练平板│◄──────────────►│ EEG-tES 上位机       │
│ 题目、提示、回答  │  RehabBridge   │ 会话、EEG、tES、安全 │
└──────────────────┘                 └──────────▲───────────┘
                                               │
                                               │ 设备协议
                                      ┌────────┴─────────┐
                                      │ EEG / tES 下位机 │
                                      └──────────────────┘
```

## 2. 背景与问题

当前脑机实验系统和失语症康复平板相互独立：

- EEG-tES 上位机能够配置刺激方案、电极、阻抗、实验时序，并记录 EEG、刺激阶段和设备事件；
- 平板能够展示失语症康复内容，并记录题目、提示、患者回答、正确性和反应时间；
- 两边尚未形成统一会话和统一时间轴。

如果两边分别启动、分别记录，治疗结束后再人工按照钟表时间对齐，将出现以下问题：

1. 两台设备初始时钟不一致；
2. 设备运行过程中存在时钟漂移；
3. 操作者分别点击开始产生人为延迟；
4. 点击“显示题目”与图片真正呈现在屏幕上的时间不同；
5. 网络发送存在延迟和抖动；
6. 无法可靠确定某一道题、某次提示或某次回答对应哪一段 EEG；
7. 人工修正过程难以追踪、复核和批量处理。

人工对时只能用于粗粒度的治疗前后整段比较，不能作为题目级 EEG 分析、ERP 分析、实时反馈或闭环研究的正式同步方式。

## 3. 产品目标

### 3.1 本方案需要实现

- 两个独立产品加入同一个患者实验会话；
- EEG-tES 上位机统一掌握本次运行的 `experimentId`、`runId` 和连接状态；
- 平板在实际显示题目、播放提示和记录回答时发送结构化事件；
- 上位机将平板事件映射到 EEG 设备时间和 `sampleIndex`；
- 断线、补发、重复、乱序和时间异常可检测、可追踪；
- 联合结果能够还原“患者当时在做什么、EEG 当时是什么、刺激处于什么阶段”；
- 后续支持单次分析、刺激前后比较和多疗程趋势比较；
- 保持 tES 安全门禁和控制权不被平板或 Agent 绕过。

### 3.2 本方案暂不实现

- 不把失语症康复全部页面搬到 EEG-tES 上位机；
- 不把原始 EEG 实时传输给平板；
- 不允许平板直接启动、停止或修改刺激；
- 不允许大语言模型直接控制刺激；
- 不在 V1.0 自动判断患者是否康复或生成确定性诊断；
- 不在 V1.0 实现基于实时 EEG 的自动刺激参数调整；
- 不把普通局域网事件同步宣称为毫秒级临床 ERP 硬件同步。

## 4. 核心产品边界

### 4.1 EEG-tES 上位机

负责：

- 创建患者实验和运行轮次；
- 校验耐受记录、刺激方案、电极映射和阻抗结果；
- 连接 EEG/tES 下位机；
- 记录 EEG 原始数据、设备时间、采样点和设备事件；
- 统一启动、监控、中止和结束实验；
- 接收平板康复事件，并写入 EEG 时间轴；
- 生成联合运行记录与同步质量报告；
- 保留所有刺激安全门禁和最终控制权。

### 4.2 失语症康复训练平板

负责：

- 加载康复训练方案；
- 展示图片、文字、选择题等训练内容；
- 播放语音或其他提示；
- 记录患者作答、正确性、反应时间和提示次数；
- 上报实际发生的任务事件；
- 显示与上位机的连接、准备、运行和中断状态；
- 本地缓存尚未确认送达的事件。

平板不负责：

- 修改刺激范式、电流、频率、时长或电极配置；
- 绕过 EEG-tES 上位机启动刺激；
- 将“任务开始”理解为“刺激已开始”；
- 根据自身网络状态判断刺激是否安全停止。

### 4.3 联合结果分析 / Agent

负责：

- 读取结构化的 EEG、刺激、任务和行为数据；
- 先执行同步质量和 EEG 数据质量检查；
- 计算任务正确率、反应时间、提示依赖等行为指标；
- 提取刺激前后或任务锁定的 EEG 片段；
- 比较单次、前后和多疗程变化；
- 生成供治疗师审核的解释和报告。

Agent 只消费已经通过边界校验的数据，不直接处理设备安全控制。

## 5. 推荐连接架构

### 5.1 物理与网络连接

推荐两端接入同一个受控局域网：

```text
医院/机构局域网
├── EEG-tES 上位机：有线网络优先，固定或可发现地址
└── 失语症平板：受控 Wi-Fi
```

推荐传输分工：

- HTTPS/REST：创建会话、加入会话、读取会话摘要和结束结果；
- WebSocket：准备状态、开始/停止指令、任务事件、心跳和时间同步；
- 本地存储：网络短暂异常时缓存未确认事件；
- 云端：治疗结束后的归档、跨设备结果汇总和远程分析，不作为实时同步的唯一链路。

蓝牙不作为首选主链路，原因是多设备管理、连接稳定性和事件时延较难统一控制。若部署环境无法提供局域网，可将蓝牙作为受限备选方案，但仍需实现相同的序列、确认、缓存和时间质量机制。

### 5.2 协议隔离

新增独立的 `RehabBridge v1`，不要让平板直接接入现有 EEG/tES 下位机控制协议。

```text
平板
  │ RehabBridge v1
  ▼
EEG-tES 联合会话网关
  │ ACQUISITION.INSERT_MARKER
  ▼
现有 DeviceSession / EEG adapter
```

这样可以确保：

- 平板输入始终被视为外部、不可信数据并在边界校验；
- 康复协议升级不会改变刺激设备控制契约；
- 即使平板出现异常消息，也不能形成刺激控制命令；
- 现有 `runId`、marker 和 `sampleIndex` 能够继续复用。

## 6. 联合康复流程

### 6.1 创建与配对

1. 操作者在 EEG-tES 上位机创建实验草稿；
2. 上位机生成 `rehabSessionId`、一次性配对码和二维码；
3. 平板扫描二维码或输入配对码；
4. 平板向上位机提交设备身份、应用版本和训练协议摘要；
5. 上位机校验协议版本、会话状态和访问令牌；
6. 配对成功后，两端显示相同的患者脱敏标识和会话编号；
7. 平板不得接收患者不必要的敏感信息。

二维码建议包含：

```json
{
  "bridgeVersion": "1.0",
  "host": "https://10.10.0.12:8443",
  "rehabSessionId": "RHS-20260824-001",
  "pairingToken": "一次性短期令牌",
  "expiresAt": "2026-08-24T10:05:00+08:00"
}
```

### 6.2 治疗前准备

1. 平板加载本次康复训练任务；
2. 平板完成音量、屏幕、麦克风和任务资源检查；
3. 平板上报 `TABLET_READY`；
4. EEG-tES 上位机继续完成刺激方案、电极配置和阻抗检测；
5. 上位机显示平板连接状态，但平板准备完成不能替代任何设备安全门禁；
6. EEG-tES 创建新的 `runId`，并将其绑定到 `rehabSessionId`；
7. 双方开始时钟同步和心跳检查。

### 6.3 统一启动

1. EEG-tES 上位机确认设备、阻抗、方案、患者和操作者门禁均通过；
2. 操作者在上位机点击“开始联合实验”；
3. 上位机先启动 EEG 连续采集并确认已收到有效 EEG frame；
4. 上位机向平板发送带计划启动时间的 `TASK_START_REQUEST`；
5. 平板确认并在计划时间进入第一阶段；
6. 平板实际显示第一个刺激材料时发送 `STIMULUS_PRESENTED`；
7. 上位机把该事件映射到 EEG `sampleIndex`；
8. 所有后续题目、提示和回答采用同一机制。

采用“先开始 EEG，再开始康复任务”的顺序，可以确保第一个任务事件之前已经存在稳定的 EEG 时间基准。

### 6.4 训练过程

以看图命名为例：

```text
平板显示“苹果”图片
  └─ STIMULUS_PRESENTED
患者开始尝试回答
  └─ RESPONSE_STARTED
检测到语音开始
  └─ SPEECH_ONSET
系统/治疗师确认“正确”
  └─ RESPONSE_RECORDED: CORRECT
本题结束
  └─ TRIAL_ENDED
```

与此同时，EEG-tES 上位机持续记录：

- EEG frame 和 `firstSampleIndex`；
- 采集、消隐、刺激、恢复阶段；
- 实际刺激设备事件；
- 阻抗、掉包、断连和异常；
- 平板事件映射后的 marker。

### 6.5 暂停、急停与结束

- 平板可以发送 `TASK_PAUSE_REQUESTED`，请求暂停训练任务；
- 上位机根据当前阶段和研究协议决定是否接受；
- 平板不能发送等价于 `STIMULATION.ABORT` 的设备命令；
- 上位机急停后向平板发送 `SESSION_ABORTED`，平板停止呈现新题目；
- 正常结束时，上位机先结束任务、确认平板事件已提交，再停止 EEG 采集；
- 双方生成各自结果，上位机生成联合会话和同步质量摘要。

## 7. 会话身份与数据关联

建议至少使用以下标识：

| 标识 | 生成方 | 作用 |
|---|---|---|
| `patientId` | 患者系统/上位机 | 关联患者，向平板仅暴露脱敏值 |
| `experimentId` | EEG-tES 上位机 | 一次实验配置草稿与历史记录 |
| `runId` | EEG-tES 上位机 | 一次实际运行轮次 |
| `rehabSessionId` | EEG-tES 上位机 | 脑机与平板的联合康复会话 |
| `trainingPlanId` | 平板/康复后台 | 本次训练方案 |
| `trialId` | 平板 | 一道题或一次训练单元 |
| `eventId` | 事件产生方 | 单个事件全局唯一标识 |
| `messageId` | 发送方 | 单次传输消息唯一标识 |

关联关系：

```text
Patient
└── Experiment
    ├── Run 1 ── RehabSession A ── Trial 1..N
    ├── Run 2 ── RehabSession B ── Trial 1..N
    └── Run 3 ── RehabSession C ── Trial 1..N
```

一个 `runId` 在 V1.0 只能绑定一个 `rehabSessionId`。重新实验必须创建新 `runId`，不得覆盖上一轮事件。

## 8. 连接与运行状态机

### 8.1 联合会话状态

```text
CREATED
  ↓
PAIRING
  ↓
CONNECTED
  ↓
SYNCING_CLOCK
  ↓
TABLET_READY
  ↓
ARMED_FOR_TASK
  ↓
RUNNING
  ├─ PAUSED
  ├─ DEGRADED
  ├─ ABORTED
  └─ COMPLETED
```

状态含义：

| 状态 | 含义 | 是否可开始任务 |
|---|---|---|
| `CREATED` | 已创建联合会话 | 否 |
| `PAIRING` | 等待平板加入 | 否 |
| `CONNECTED` | 通信建立，但未完成同步 | 否 |
| `SYNCING_CLOCK` | 正在估算时钟偏移和延迟 | 否 |
| `TABLET_READY` | 平板资源和训练计划就绪 | 仍需上位机门禁 |
| `ARMED_FOR_TASK` | 双方准备完成，等待操作者启动 | 是 |
| `RUNNING` | 联合训练进行中 | 已运行 |
| `PAUSED` | 任务暂停，是否继续采集按协议决定 | 否 |
| `DEGRADED` | 连接或同步质量下降 | 按协议暂停或继续并标记 |
| `ABORTED` | 本轮中止 | 否 |
| `COMPLETED` | 正常完成 | 否 |

### 8.2 状态控制原则

- 服务端/上位机是联合会话状态权威；
- 平板只能上报自身状态和请求，不能单方面把会话改成 `RUNNING`；
- 状态变化必须带版本号，防止旧消息覆盖新状态；
- 每次状态变化写入不可覆盖的审计事件；
- EEG/tES 设备状态与康复会话状态分开保存，界面可以联合展示但不能混为同一状态。

## 9. RehabBridge v1 消息契约

### 9.1 通用消息信封

```json
{
  "protocolVersion": "1.0",
  "messageId": "MSG-01J6...",
  "messageType": "REHAB.STIMULUS_PRESENTED",
  "rehabSessionId": "RHS-20260824-001",
  "runId": "RUN-001",
  "sourceDeviceId": "TABLET-003",
  "sequence": 284,
  "sourceMonotonicTimeUs": 882734500,
  "sourceWallTime": "2026-08-24T10:12:35.482+08:00",
  "sentAt": "2026-08-24T10:12:35.486+08:00",
  "payload": {}
}
```

约束：

- `protocolVersion` 必填；
- `messageId` 用于消息级去重；
- `sequence` 在一个平板连接会话内单调递增；
- `sourceMonotonicTimeUs` 用于时钟映射，不能只依赖格式化日期；
- `sourceWallTime` 用于审计和人工查看，不作为最终 EEG 对齐依据；
- 外部消息必须通过类型、范围、会话状态和权限校验；
- 未识别字段可以忽略，未识别的必需消息类型必须返回明确错误；
- 新版本优先增加可选字段，不修改既有字段含义。

### 9.2 平板上报事件

| 消息类型 | 触发时机 | 关键字段 |
|---|---|---|
| `REHAB.TABLET_READY` | 训练资源加载完成 | `trainingPlanId`, `appVersion` |
| `REHAB.TRIAL_STARTED` | 一道题开始 | `trialId`, `taskType`, `difficulty` |
| `REHAB.STIMULUS_PRESENTED` | 图片/文字实际呈现 | `trialId`, `stimulusId`, `modality` |
| `REHAB.AUDIO_STARTED` | 提示音实际开始播放 | `trialId`, `audioId` |
| `REHAB.HINT_PRESENTED` | 提示实际呈现 | `trialId`, `hintType`, `hintIndex` |
| `REHAB.RESPONSE_STARTED` | 患者开始操作或尝试回答 | `trialId`, `inputType` |
| `REHAB.SPEECH_ONSET` | 检测到语音开始 | `trialId`, `detector`, `confidence` |
| `REHAB.RESPONSE_RECORDED` | 记录作答结果 | `trialId`, `result`, `responseTimeMs` |
| `REHAB.TRIAL_ENDED` | 本题结束 | `trialId`, `endReason` |
| `REHAB.TASK_PAUSE_REQUESTED` | 平板/治疗师请求暂停 | `reason` |
| `REHAB.TASK_RESUME_REQUESTED` | 请求恢复 | `reason` |
| `REHAB.TABLET_FAULT` | 平板发生异常 | 标准错误结构 |

事件应尽量在“实际发生”回调产生，而不是在操作命令发出时产生。例如图片应在渲染完成回调记录，音频应在实际开始播放回调记录。

### 9.3 上位机下发消息

| 消息类型 | 用途 |
|---|---|
| `REHAB.PAIRING_ACCEPTED` | 配对成功并返回会话摘要 |
| `REHAB.SYNC_REQUEST` | 发起时钟同步测量 |
| `REHAB.TASK_START_REQUEST` | 请求平板按计划时间启动任务 |
| `REHAB.TASK_PAUSE` | 暂停呈现新任务 |
| `REHAB.TASK_RESUME` | 恢复任务 |
| `REHAB.TASK_STOP` | 正常结束任务 |
| `REHAB.SESSION_ABORTED` | 上位机中止联合会话 |
| `REHAB.EVENT_ACKNOWLEDGED` | 确认事件已持久化 |
| `REHAB.EVENT_REJECTED` | 拒绝非法或不适用事件 |

`TASK_START_REQUEST` 只代表康复任务启动，不代表刺激启动。刺激阶段仍由现有 `STIMULATION.ARM` 和 `STIMULATION.START` 控制。

```json
  "runId": "RUN-001",

  "sequence": 284,
  "sourceMonotonicTimeUs": 882734500,
```

```json
}
```

### 9.5 确认、去重与补发

- 平板发送事件后保留本地副本，直到收到 `EVENT_ACKNOWLEDGED`；
- 超时未确认时使用同一 `messageId` 重发；
- 上位机按 `messageId` 幂等处理，重复消息不能生成多个 marker；
- 上位机检查 `sequence`，发现缺口时请求补发缺失范围；
- 乱序事件可以接收，但必须按源时间和序列重建，并记录乱序状态；
- 会话结束前，双方执行一次事件数量和最后序列号核对；
- 无法补齐的事件缺口写入同步质量报告，不能静默忽略。

### 9.6 统一错误结构

```json
{
  "error": {
    "code": "SESSION_STATE_CONFLICT",
    "message": "当前会话未进入运行状态，不能接收题目事件",
    "recoverable": true,
    "details": {
      "expectedState": "RUNNING",
      "actualState": "TABLET_READY"
    }
  }
}
```

建议至少定义：

- `PROTOCOL_VERSION_UNSUPPORTED`；
- `PAIRING_TOKEN_INVALID`；
- `SESSION_NOT_FOUND`；
- `SESSION_STATE_CONFLICT`；
- `RUN_ID_MISMATCH`；
- `MESSAGE_SCHEMA_INVALID`；
- `SEQUENCE_GAP`；
- `CLOCK_SYNC_UNAVAILABLE`；
- `EVENT_TIME_OUT_OF_RANGE`；
- `EVENT_DUPLICATED`；
- `EVENT_STORAGE_FAILED`；
- `TABLET_CONNECTION_LOST`。

## 10. REST 与 WebSocket 接口建议

### 10.1 REST 资源

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/v1/rehab-sessions` | 上位机创建联合会话 |
| `GET` | `/api/v1/rehab-sessions/{id}` | 查询会话摘要和状态 |
| `POST` | `/api/v1/rehab-sessions/{id}/pair` | 平板使用一次性令牌配对 |
| `POST` | `/api/v1/rehab-sessions/{id}/close` | 正常结束并封存会话 |
| `GET` | `/api/v1/rehab-sessions/{id}/sync-report` | 获取同步质量报告 |
| `GET` | `/api/v1/rehab-sessions/{id}/events` | 分页查询联合事件 |

所有写操作都要校验调用端身份、会话版本和当前状态。事件列表必须分页，禁止一次性返回无限增长的数据。

### 10.2 WebSocket

```text
wss://<host>/api/v1/rehab-sessions/{rehabSessionId}/stream
```

用途：

- 双向心跳；
- 时钟同步请求和响应；
- 状态变化；
- 任务开始、暂停、恢复和停止；
- 平板任务事件；
- ACK、拒绝和缺口补发。

生产部署优先使用 TLS。机构内网使用私有证书时，需要明确证书分发和更新机制，不能长期关闭证书校验。

## 11. 时间同步与 EEG 采样点映射

### 11.1 权威时间基准

最终分析以 EEG 设备的单调时间和 `sampleIndex` 为权威，不以平板墙上时钟为权威。

每个事件保留四类时间：

1. 平板单调时间：事件在平板实际发生的时间；
2. 平板墙上时间：用于日志阅读；
3. 上位机接收时间：用于网络延迟和审计；
4. EEG 设备时间/采样点：用于最终脑电截取和分析。

不得用上位机接收时间覆盖平板实际发生时间，也不得只保存最终 `sampleIndex` 而丢失映射过程。

### 11.2 网络时钟同步

建议采用类似四时间戳的往返测量：

```text
上位机发送 t1
平板接收 t2
平板返回 t3
上位机接收 t4
```

上位机通过多次测量估算：

- 平板与上位机的时钟偏移；
- 当前网络往返延迟；
- 延迟抖动；
- 运行过程中的时钟漂移。

建议启动前连续测量多轮，剔除明显高延迟样本；运行中周期性重测。事件映射使用事件发生时附近的偏移估计，不能整场实验只使用一次初始偏移。

### 11.3 映射到 EEG sampleIndex

已有 EEG frame 包含：

- `firstSampleIndex`；
- `sampleCount`；
- `sampleRateHz`；
- `deviceTimeUs` 或帧对应设备时间。

上位机将康复事件时间换算到 EEG 设备时间后，定位到最邻近采样点：

```text
tablet event time
  → host monotonic time
  → EEG device time
  → EEG sampleIndex
```

若设备支持 `ACQUISITION.INSERT_MARKER`，上位机应请求设备/adapter 返回最终 marker 的 `sampleIndex`。若真实设备不支持硬件 marker，则由上位机网关根据最近 EEG frame 估算，并将 `mappingQuality` 标记为较低等级。

### 11.4 同步质量等级

建议定义：

| 等级 | 说明 | 可用于 |
|---|---|---|
| `HARDWARE_TRIGGERED` | 硬件触发器直接进入采集设备 | 毫秒级研究，仍需实测验证 |
| `NETWORK_SYNCED` | 局域网对时并映射到采样点 | 多数秒级任务和频段分析 |
| `HOST_RECEIVED_ONLY` | 仅有上位机接收时间 | 粗粒度任务分析，谨慎使用 |
| `MANUALLY_ALIGNED` | 人工对时 | 仅整段前后比较，不用于题目级结论 |
| `UNSYNCED` | 无法可靠映射 | 不进入任务锁定分析 |

同步等级必须写入每个事件及整次运行的同步报告。

### 11.5 工程精度目标

以下是产品研发验收建议，不是通用临床标准：

- 普通任务频段/多秒窗口分析：优先达到网络同步误差估计 P95 不高于 50 ms；
- 题目级正确/错误分段：不得存在未解释的秒级偏移；
- ERP 或其他毫秒敏感研究：采用硬件触发或经过专项验证的高精度同步，目标由研究协议单独定义；
- 每次运行必须输出实际测得的偏移、往返延迟、抖动、漂移和不可映射事件比例。

不能因为使用了 WebSocket 就宣称已达到某个时间精度，必须通过测试仪器和端到端实验验证。

## 12. 断线、重连与降级处理

### 12.1 心跳

- 双方定期发送心跳；
- 连续多个心跳未确认后进入 `DEGRADED`；
- 超过协议阈值进入 `DISCONNECTED`；
- 阈值必须配置化并记录到协议版本，不能仅写死在前端。

### 12.2 平板短暂断线

- 平板将事件写入本地持久队列；
- 重连后按原 `messageId` 和 `sequence` 补发；
- 上位机幂等接收并请求缺失序列；
- 补发事件仍保留原始单调时间，不得改成重连时间；
- 若时钟映射在断线区间无法可靠恢复，事件标记为 `HOST_RECEIVED_ONLY` 或 `UNSYNCED`。

### 12.3 是否继续训练

推荐默认策略：

- 尚未开始：连接或同步不合格时禁止联合启动；
- 任务运行中短暂断线：暂停呈现新题目，保留 EEG 采集；
- 恢复连接且同步重新合格：由操作者或协议确认后恢复任务；
- 长时间断线：中止本轮联合任务，并保留已完成数据；
- 如果刺激正在输出：由 EEG-tES 自身安全协议决定继续、暂停或安全中止，不能依赖平板发出停止命令。

某些研究协议可能允许断线期间继续训练，但必须把该区间明确标记为不同步，并禁止进入题目级 EEG 分析。

### 12.4 EEG/tES 设备异常

- EEG 掉包、设备时间回退、关键通道脱落或刺激故障仍按现有设备协议处理；
- 上位机在形成安全状态后通知平板暂停或停止任务；
- 平板显示“设备异常，等待操作者处理”，不得自行推断刺激已经安全停止；
- 所有异常、命令、确认和最终安全状态进入审计日志。

## 13. 安全与权限边界

### 13.1 指令白名单

平板允许发送：

- 准备状态；
- 康复任务事件；
- 暂停/恢复请求；
- 平板自身异常；
- 心跳和同步响应。

平板禁止发送：

- 刺激参数修改；
- 电极映射修改；
- 阻抗结果覆盖；
- `STIMULATION.ARM`；
- `STIMULATION.START`；
- 伪造设备安全状态；
- 删除或覆盖既有运行记录。

### 13.2 身份与访问

- 配对令牌一次性使用、短期有效并绑定会话；
- 平板配对成功后获得最小权限的会话令牌；
- 会话令牌不能访问其他患者或历史实验；
- 患者身份优先使用脱敏标识；
- 操作者身份、关键操作和导出行为写入审计；
- 敏感数据传输和存储策略需由安全与合规团队确认。

### 13.3 数据可信性

- 平板事件属于外部输入，必须验证类型、长度、枚举、时间范围和会话状态；
- 自动语音检测结果必须记录算法版本和置信度；
- “回答正确”要记录判定来源：治疗师、规则、语音模型或人工复核；
- Agent 生成的解释与底层结构化结果分开保存；
- 人工修正事件必须保留原值、修改值、操作者、时间和原因。

## 17. 联合分析方案

分析必须按以下顺序进行：

```text
同步质量
  ↓
EEG 数据质量
  ↓
任务行为指标
  ↓
任务锁定 EEG 特征
  ↓
刺激前后比较
  ↓
多次疗程趋势
  ↓
Agent 解释与报告
```

### 17.1 同步质量

- 事件是否完整；
- 是否存在序列缺口；
- 时间偏移和漂移是否可估计；
- 各事件映射质量；
- 是否存在不可分析区间。

### 17.2 EEG 数据质量

- 运行前阻抗；
- 运行中坏通道、脱落、平线、饱和和异常噪声；
- 眼动、肌电、运动等伪迹；
- 丢包、插值、设备时间异常；
- 刺激中伪迹区间；
- 每个 trial 的可用 EEG 比例。

阻抗通过仅表示开始前电极接触满足当前门禁，不等于整场 EEG 都可以分析。

### 17.3 行为指标

- 总题数和完成题数；
- 首次正确率与最终正确率；
- 反应时间；
- 提示次数和提示类型；
- 自动判定与治疗师复核一致率；
- 不同任务类型和难度的表现。

### 17.4 EEG 分析

V1.0 可优先支持：

- 训练前后静息 EEG 比较；
- 题目呈现后多秒窗口的频段和空间特征；
- 正确与错误 trial 的描述性比较；
- 刺激前、刺激后和恢复阶段比较；
- 多次疗程的个体内趋势。

刺激中 EEG 默认标记为高伪迹区间，不直接用于普通脑状态结论。只有在硬件、算法和验证方案明确后，才开放刺激中实时脑状态分析。

### 17.5 Agent 输出边界

推荐输出：

> 本次联合训练共完成 40 题，其中 35 题具有完整任务事件，31 题具有可用 EEG。与上次相比，首次正确率提高，平均反应时间缩短；刺激后某项 EEG 描述性指标连续两次出现同方向变化。当前结果提示存在稳定趋势，仍需结合更多疗程和临床评估确认。

禁止输出：

> EEG 已证明患者语言功能恢复 32%，系统应自动提高刺激强度。

## 18. 分阶段落地建议

### 阶段 0：流程确认

目标：确认真实治疗流程。

- 明确两端当前由谁操作、何时启动、何时结束；
- 明确平板现有事件和数据结构；
- 明确 EEG 设备 marker 能力；
- 明确机构局域网和设备部署条件；
- 明确需要秒级分析还是毫秒级 ERP。

### 阶段 1：联合会话 MVP

目标：取消人工对时，支持题目级数据关联。

- 二维码/连接码配对；
- `rehabSessionId` 与 `runId` 绑定；
- WebSocket 持续连接和心跳；
- 上位机统一启动；
- 核心任务事件上报；
- 网络对时和 `sampleIndex` 映射；
- 事件 ACK、去重和本地缓存；
- 联合结果导出。

### 阶段 2：可靠性与质控

目标：让联合数据可批量分析。

- 周期性时钟漂移校正；
- 缺口检测、补发和同步报告；
- 运行中 EEG 信号质控；
- trial 可用性判定；
- 断线暂停与恢复状态机；
- 回放联合任务与 EEG 时间轴。

### 阶段 3：结果分析与疗程比较

目标：形成治疗师可用的结果产品。

- 行为指标和 EEG 指标联合展示；
- 刺激前后比较；
- 多次疗程趋势；
- 结构化报告；
- Agent 生成解释，治疗师审核发布。

### 阶段 4：实时反馈研究

目标：在经过验证的特定任务中研究实时反馈。

- 在线伪迹检测；
- 个体化脑状态模型；
- 向平板返回经过批准的反馈变量；
- 固定安全边界内的任务难度调整；
- 对照组、盲法和临床结果验证。

实时反馈与自动刺激调整不得在没有专项安全与临床验证的情况下合并上线。

## 19. MVP 验收标准

### 19.1 配对与身份

- 上位机能够创建联合会话并生成一次性配对码；
- 平板只能加入有效且未被占用的会话；
- 两端显示一致的 `rehabSessionId` 和脱敏患者标识；
- 重新实验生成新的 `runId`，不覆盖旧记录。

### 19.2 运行

- 平板未准备或同步不合格时，联合启动不可用；
- EEG 采集成功后才向平板发送任务启动；
- 平板的题目、提示、回答和结束事件能够实时进入上位机时间轴；
- 平板不能通过任何接口启动或修改刺激；
- 急停和设备异常优先由 EEG-tES 安全逻辑处理。

### 19.3 数据

- 每个接受事件都有唯一 `messageId`、`sequence` 和 ACK；
- 重复发送不会生成重复 marker；
- 事件能够映射到 EEG `sampleIndex`；
- 同步方法、误差估计和质量等级可查看、可导出；
- 断线补发保留原始事件时间；
- 不可映射事件明确标记，不被默认纳入题目级分析。

### 19.4 测试

- 正常连接、启动、运行和结束；
- 平板在开始前断线；
- 平板在任务中短暂断线并补发；
- 平板长时间断线；
- 事件重复、乱序和序列缺口；
- 平板时间跳变和重启；
- EEG 掉包和设备时间回退；
- 上位机急停；
- 刺激设备故障；
- 联合 Run Bundle 导出和回放；
- 长时间运行后的时钟漂移；
- 端到端事件延迟与采样点映射误差测试。

## 20. 待确认事项

1. 失语症平板现有技术栈、操作系统和是否支持 WebSocket；
2. 平板目前能够产生哪些任务事件，事件是在操作命令还是实际呈现回调触发；
3. 患者回答正确性由谁判定，是否需要治疗师复核；
4. 平板是否使用麦克风，语音原始数据是否允许保存；
5. EEG 真机是否支持硬件 marker/trigger 及返回 `sampleIndex`；
6. 机构网络是否允许平板直连上位机，是否需要独立网关；
7. 本阶段分析目标是整段、题目级频段还是毫秒级 ERP；
8. tES 与康复任务是同时进行、前后进行还是间歇交替；
9. 平板断线时，当前临床/研究协议要求暂停任务、继续任务还是中止；
10. 如果刺激正在输出且平板断线，正式安全策略如何定义；
11. 联合数据的保存位置、保留周期、权限、脱敏和导出规则；
12. 同步精度的正式验收方法和测试设备；
13. 是否需要与医院患者系统或康复处方系统关联；
14. 谁是联合结果的审核者和发布者。

## 21. 推荐首先向康复平板团队确认的问题

> 我目前理解是，患者戴着 EEG/tES 设备，同时在平板上做失语症康复训练。平板记录题目、提示、回答和反应时间，脑机设备记录对应的 EEG 和刺激过程，之后把两边数据结合起来分析单次和多次治疗变化。请问目前实际治疗中，两套设备是怎样启动、配合和结束的？两边现在是人工分别操作并在治疗后手工对时间，还是已经通过蓝牙、局域网、接口或其他方式自动连接？平板能否在图片实际出现、提示播放和患者回答时输出带时间戳的事件？

## 22. 最终原则

1. 两个产品可以独立，但一次联合治疗必须共享会话身份；
2. EEG 设备时间和采样点是分析权威时间基准；
3. 平板事件必须实时或可追踪地同步，不能依赖人工对时；
4. 同步质量和 EEG 质量必须先于医学解释；
5. 平板、分析模型和 Agent 都不能绕过刺激安全门禁；
6. 先实现可靠记录和多次比较，再考虑实时反馈和自适应治疗。
